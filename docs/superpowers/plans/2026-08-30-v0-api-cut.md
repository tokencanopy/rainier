# Rainier `/v0/` API Clean-Cut Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Complete one task, commit it, report the commit and verification output, and stop for reviewer approval before starting the next task.

**Goal:** Move every active Rainier REST, WebSocket, runner, CLI, test, script, and documentation path from the retired HTTP path to `/v0/` without changing behavior or retaining a compatibility alias.

**Architecture:** This is a deliberately mechanical contract cut after Plan 5 and PR #15. Route literals remain explicit at transport call sites and in external contract tests so a shared version constant cannot allow a wrong server and wrong client to agree. The runner wire major `rwire.Proto == 1` is independent of the HTTP path and remains unchanged.

**Tech Stack:** Go 1.25, `net/http`, `coder/websocket`, shell acceptance scripts, existing dependencies only.

**Spec:** In `tokencanopy/rainier-cloud` commit `096811c`, read `docs/product/hosted-product-prd.md` Section 14 and `docs/architecture/adr-0001-oss-cloud-composition.md` Migration Sequence item 1.

## Global Constraints

- Begin from a freshly fetched `origin/main` containing PR #15 (`2d055a6` or a descendant) in `.worktrees/v0-api-cut`; never edit the shared root checkout.
- Change HTTP path versioning only. Do not rename Go packages, change the `module rainier` declaration, move files, extract the control service, or modify `internal/rwire.Proto` in this plan.
- The only supported HTTP surface after this plan is `/v0/`; do not register redirects, aliases, or duplicate handlers for the retired HTTP path.
- Preserve HTTP methods, request/response bodies, status codes, headers, error envelopes, authorization, pagination, idempotency, WebSocket behavior, and runner protocol bytes.
- Keep `/healthz` unversioned.
- Do not introduce a shared path-prefix constant into external contract tests. Tests must assert literal `/v0/...` paths.
- Use only synthetic accounts, repositories, tokens, session IDs, and output in tests and documentation.
- After every task run `gofmt` on changed Go files, `go test` for the affected packages, and `git diff --check`.
